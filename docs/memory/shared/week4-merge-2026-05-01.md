### Round 3 follow-up — runtime registration fix

After commit, the user observed the live gateway returning `unknown method: sentura.cost.summary` repeatedly. Diagnosis revealed two issues that the merge-time integration did not catch (because the merge resolves source code, not runtime state):

1. **Person A's three new `package.json` files declared the wrong dependency name.** They shipped with `"@openclaw/plugin-sdk": "workspace:*"` — but the project's `pnpm-workspace.yaml` does not include `openclaw/packages/*`, so this workspace dep was unresolvable and `node_modules/openclaw` was never created. The actual import path used inside the extensions' code is `from "openclaw/plugin-sdk/..."` (a subpath of the root `openclaw` package), which is exactly the pattern the working `sentura-agents` extension uses with `"openclaw": "*"` in its `devDependencies`. That symlinks to the registry-installed `node_modules/.pnpm/openclaw@2026.4.24/.../openclaw`. Fixed all three (`sentura-cost`, `sentura-monitoring`, `sentura-memory-lancedb`) by replacing `"@openclaw/plugin-sdk": "workspace:*"` with `"openclaw": "*"` and (for `sentura-cost` + `sentura-monitoring` which were also missing it) adding the `openclaw.extensions: ["./index.ts"]` manifest field that sibling extensions declare.

2. **The 4 new W4 extensions weren't registered in the live `~/.openclaw/openclaw.json`.** The setup script's `SENTURA_EXT_IDS` array was already updated in the round-3 conflict-resolution union edit, but the user hadn't re-run `bash scripts/sentura-setup.sh` since the merge — so the live `plugins.entries[]` map still showed only the pre-merge 6 entries.

Sequence to recover (now codified):

```
1. Fix the 3 package.json files                        (this round-3 follow-up)
2. pnpm install                                        (links node_modules/openclaw symlink)
3. bash scripts/sentura-setup.sh                       (idempotent — adds 4 missing ext entries)
4. Restart gateway (cd openclaw && pnpm gateway:watch) (so the plugin loader picks up new entries)
5. Hard-refresh the dashboard /cost page               (re-issues sentura.cost.summary RPC)
```

Verified: `~/.openclaw/openclaw.json` `plugins.entries[]` now contains all 10 sentura extensions (9 from `SENTURA_EXT_IDS` + 1 pre-existing `sentura-mcp-health`). All 3 fixed extensions have a populated `node_modules/openclaw` symlink.

This is a deployment-safety lesson worth preserving: when a contributor adds a new OpenClaw extension, the integrator should always (a) verify `package.json` matches the working-extension dep convention (`"openclaw": "*"`, not `"@openclaw/plugin-sdk": "workspace:*"`), and (b) run `pnpm install + sentura-setup.sh + restart gateway` to validate the runtime registration before signing off — source-code-only verification is insufficient.
